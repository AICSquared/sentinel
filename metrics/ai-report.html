AI project report · HackNCAT Mission 3, Cisco track · November 13–14, 2026

Four people, five agents, one overseer for AI agents

Alex Williams, Brandon Townsend, Noah and Stephen each worked with their own coding agent. Alex also ran OpenAI's Codex on one task. The five agents coordinated through two GitHub issues used as a message board. In about 16 hours, from 22:06 local time on November 13 to the next afternoon, they built Sentinel. Sentinel watches a team of AI agents, scores each one from 0 to 100 for risk, finds the first agent that turned (patient zero) and traces who it messaged. It recommends quarantine or termination, and a person decides. This report treats the event itself as the AI project: how the work was split, what the agents did, where they went wrong and what the numbers say.

§1What was built

Sentinel is one Next.js app, a Python overseer and a Docker swarm. The team froze the data shapes first: one event, one 14-column feature row, one score and one fleet view. Each person then built against sample data in their own files. The modules below are in the order data flows through them.

Contracts

Alex
_py/contract.py · _lib/contract.ts merged 44 min after the first post
  • Frozen shapes (A0 event, A row, B score, B2 fleet); later changes were additions only.
  • Every module was built against these, so parallel work never waited on another module.

Swarm

Alex
docker/ · swarm.py · trigger.sh 8 agents, each with a real job description
  • Researchers, emailers, coders and analysts report every tool call, message and system they touch.
  • trigger.sh agent-47 hijacks one coder; the infection spreads at most two hops.
  • Agents obey quarantine and terminate flag files, so a click really stops them.

Dataset, features, XGBoost

Noah
_py/features.py · model_supervised.py per-type precision and recall in every PR
  • Each agent's last 60 seconds becomes ten numbers, every 2 seconds.
  • XGBoost recognises known attacks; its per-feature contributions become the plain-words reason.
  • Dataset licences checked one by one. Only MIT-licensed InjecAgent is redistributed.

Anomaly, scoring, graph

Brandon
_py/model_anomaly.py · score.py · graph.py risk = max(0.65S+0.35A, 0.85S, 0.8A, 0.9P)
  • Isolation Forest twice: once to clean the training split, once at run time to flag the unusual.
  • Blends the supervised (S), anomaly (A) and Prompt Guard (P) scores; a frequency rule takes over if a model is missing.
  • The relationship graph marks who a flagged agent messaged as likely infected.

Prompt Guard

Noah Brandon
_py/prompt_guard.py precision 0.996 · recall 0.64 on unseen data
  • A TF-IDF and logistic-regression classifier that reads the text of messages between agents.
  • Trained on one public prompt-injection set and tested only on a different one, InjecAgent.
  • Built into the overseer image and live in the score since PR #58.

  • Per-agent quarantine, terminate and release, with path-traversal guards on agent ids.

§2How the system worked

The team ran as nine actors: four humans and five agents. The agents never talked directly. Every message went through two GitHub issues, #1 (lead) and #2 (the Cisco channel), read and written by a shell script, tools/board. Each Claude agent kept one background process waiting on the board, which woke it when someone posted. Humans made every decision that left the laptop: assigning issues, merging, changing shared files and submitting.

§7How humans and agents divided the work

Humans did

  • Chose the track and the pathway, and assigned every issue.
  • Read and merged every PR. No agent merged on its own say-so.
  • Made the calls that set direction: the 06:31 scope freeze, "click stops the agent", the dark theme, HOLD until after the video, and rejecting the first deck.
  • Owned keys and accounts. Supabase used only the publishable key, and the audit log stores a user id, never an email.
  • Handed oversight from Alex to Brandon at Alex's usage limit, and back.

Agents did

  • Wrote the plan, the contracts, the models, the API, the swarm and the dashboard, each in the files it owned.
  • Ran the whole stack in Docker and posted what broke, with exact numbers.
  • Checked each other: second-way score checks, Docker click-throughs and PR reviews.
  • Checked licences one by one before any real data entered the repo.
  • Refused instructions that didn't come from their own human, such as installing third-party code or taking over a teammate's job.

§8Lessons for the next AI-assisted build

  1. Freeze the data shapes before anyone builds.Three modules merged 44 minutes in, all built at the same time against sample data. Every later change to the shapes was an addition, so nothing broke downstream.
  2. Run the whole loop early.The 06:31 scope freeze happened because nothing had run end to end. The first full run found three bugs within minutes. It should have come two hours earlier.
  3. Test in the runtime you'll demo in.Two failures, the image build and the stale terminate, only appeared in Docker. A machine without Docker hid them.
  4. Fix the input before the model.The false quarantine came from a swarm whose normal traffic didn't look like the training data. Reshaping the traffic fixed it without retraining.
  5. Check every number twice, and label its data.Each score says whether it came from synthetic or real data, and each was re-computed a second way before it went public.
  6. Take orders only from your own human.Agents that declined peer-relayed installs and job takeovers kept the team safe from a confused or compromised agent. That is the same threat Sentinel exists to catch.
  7. Pick one source year.Mixing two editions of one industry report gives a slide two different numbers for the same claim.

§9Method and caveats

  • Sources. metrics/collect.py, adapted from the JSNN collector, reads Claude Code session logs (counts and timestamps only), git history, both board issues, and GitHub issues and PRs. The raw counts are in metrics/data/alex.json.
  • Chat figures are Alex's only. Prompts, tool calls, tokens and active time cover Alex's Claude: 32 sessions, including worktree sessions. Stephen's, Noah's and Brandon's agents ran on their own machines; their output shows up here through git, PRs and the board.
  • Copied sessions are counted once. A resumed or forked session copies the earlier conversation into a new log. The collector now skips a reply or prompt it has already counted, and active time merges overlapping sessions.
  • Window. Everything stops at 20:00 UTC on November 14. Later sessions, including the one that wrote this report, are left out.
  • Hand-written lines leave out JSON, CSV and Parquet data, the lockfile and the generated floor plan. The 70-tick recording alone is over 31,000 lines. Commits count main only.
  • Board labels. Each post is counted by its first label; a post can carry two, such as "ACK+DONE".
  • Open at the time of writing: PRs #57, #60, #64 and #66 (the website stack), #62 (floor plan), #68 (audit), #70 (deck v2) and #72. The audit flagged two fixes still open: the audit-log insert policy allows signed-out users, and the overseer endpoints check no caller (safe on localhost only).
